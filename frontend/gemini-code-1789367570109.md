# KẾ HOẠCH FRONTEND: STUDENT MANAGEMENT SYSTEM

## 1. Tổng quan & Yêu cầu Kỹ thuật
*   **Mục tiêu:** Xây dựng giao diện web quản lý học sinh và phụ huynh dành cho Admin.
*   **Công nghệ FE:** Angular 18+ (Standalone Components, RxJS, Signals), Tailwind CSS. 
*   **Yêu cầu cốt lõi:** Giao diện Responsive (ưu tiên hiển thị tốt trên mọi thiết bị), xử lý triệt để Memory Leak bằng cách dọn dẹp các luồng `RxJS` (dùng `takeUntilDestroyed` hoặc `AsyncPipe`).

---

## 2. Cơ chế Tương tác Hệ thống (FE & BE)
Dự án áp dụng kiến trúc tách rời (Decoupled Architecture), FE và BE hoạt động độc lập và giao tiếp với nhau qua API:

*   **Bản hợp đồng API (API Contract):** BE (.NET 8) và FE (Angular 18) thống nhất dữ liệu qua tài liệu Swagger (`API_DOCS.md`). BE xuất dữ liệu từ Database ra định dạng **JSON**.
*   **Luồng Xác thực (Authentication):** FE gửi thông tin đăng nhập lên BE. BE kiểm tra và trả về một **JWT Token**. FE lưu Token này lại và tự động đính kèm (via `HttpInterceptor`) vào tiêu đề (`Header`) của mọi request gõ cửa BE sau đó.
*   **Quy trình Phát triển Song song (Parallel Development):** 
    *   Trong lúc BE đang xây dựng Database và logic, FE sẽ tự tạo **Mock Data (Dữ liệu giả)** dựa trên cấu trúc JSON của API Contract để dựng layout, làm chức năng và test luồng.
    *   Khi BE hoàn thành, FE chỉ cần thay đổi Base URL (`https://localhost:...`), xóa Mock Data và hệ thống sẽ kết nối liền mạch.

## 3. Lộ trình Thực thi (Plans & Phases)

### Plan 1: Khởi tạo Kiến trúc & Phân hệ Xác thực
*   **Phase 1.1 (Setup):** Khởi tạo project Angular 18, cài Tailwind CSS, thiết lập cấu trúc thư mục (Core, Features, Shared) và cấu hình Routing.
*   **Phase 1.2 (Auth UI & Mock):** Dựng form Đăng nhập, viết `AuthService` với logic trả về mock JWT Token.
*   **Phase 1.3 (Bảo mật Route):** Viết `AuthGuard` chặn các trang nội bộ (chưa đăng nhập không cho vào). Dựng giao diện trang Thông tin cá nhân (Profile) cơ bản.

### Plan 2: Phát triển Phân hệ Quản lý (CRUD) bằng Mock Data
*   **Phase 2.1 (Mock Services):** Dựa trên `API_DOCS.md`, tạo định nghĩa Interface và Mock Data cho danh sách Học sinh và Phụ huynh.
*   **Phase 2.2 (UI Danh sách):** Xây dựng Component bảng (Table) có phân trang, thanh tìm kiếm. Sử dụng Tailwind để đảm bảo bảng tự co giãn, không vỡ layout trên điện thoại.
*   **Phase 2.3 (UI Form & Xử lý n-n):** Dựng form Thêm/Sửa học sinh. Tại trang chi tiết Học sinh, thiết kế UI dạng Tab hoặc Modal cho phép Admin gán hoặc gỡ bỏ liên kết với Phụ huynh.

### Plan 3: Tích hợp API Backend & Nghiệm thu
*   **Phase 3.1 (Tích hợp API):** Thiết lập `HttpInterceptor` để gắn JWT Token. Gỡ bỏ toàn bộ Mock Data, thay thế bằng `HttpClient` gọi xuống API thật của .NET đang chạy ở Localhost.
*   **Phase 3.2 (Xử lý Lỗi):** Bắt các mã lỗi (400, 401, 404, 409) từ BE trả về và hiển thị thông báo (Toast/Alert) tương ứng trên giao diện FE.
*   **Phase 3.3 (Tối ưu Hiệu năng):** Rà soát lại toàn bộ Component, đảm bảo 100% các request API hoặc event listener đều được "hủy đăng ký" (unsubscribe) khi Component bị hủy, đảm bảo không rò rỉ bộ nhớ.
